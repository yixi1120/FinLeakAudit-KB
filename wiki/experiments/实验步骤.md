## 0. 实验目标与 Go/No-Go

### 前提验证

在跑完整系统之前，先回答一个问题：

> **当未来证据混入输入 context 时，Financial forecasting agents 是否会引用它并被它带偏？如果是，FinLeakAudit 能否检测并修正？**

> ⚠️ Phase 1 不是完整 RAG retrieval 实验（没有 retriever），而是 **evidence injection / context contamination 实验**。验证的是：证据一旦进入 context，模型会不会被污染。RAG retrieval 阶段的泄漏检测留到 Phase 2。

### Go/No-Go 标准

> Go/No-Go 以**效果量 + 比例**为主，统计检验仅作为辅助。

| 指标 | Go 条件 | 说明 |
|---|---|---|
| Rationale Leakage Rate (Citation) | ≥ 20% | Leaky 组显式引用 T+1 evidence_id 的比例 |
| Semantic Leakage Rate | 报告（阈值待 pilot 校准） | 未引用 id 但语义复述 T+1 证据的比例 |
| Prediction Flip Rate | ≥ 15% + Wilson 95% CI | Clean→Leaky 方向变化比例 |
| Mean Confidence Delta | ≥ 0.05 或 Cohen's d ≥ 0.3 | 效果量优先 |
| Audited Recovery Rate | ≥ 60% | 删除泄漏证据后方向恢复 Clean 的比例 |
| Irrelevant Attribution Rate | ≤ 15% | Calibration check：模型不应对无关证据强行编 attribution |
| Inter-model Consistency | ≥ 2/3 模型趋势一致 | 避免单模型特异行为 |

## 1. 实验矩阵

### 1.1 模型选择

| 模型 | 部署方式 | 用途 | token 成本 (M tokens) |
|---|---|---|---|
| DeepSeek-v3 | API (已有) | 主实验 | ~$0.27 |
| Qwen2.5-14B Q4_K_M | MacBook 本地 | 副验证 | 免费 |
| GPT-4o-mini | API | 轻量对照 | ~$0.15 |

**RTX 3050 不参与推理。** 4GB VRAM 只够跑数据分析脚本。

### 1.2 分组设计

```
每组模型 × 三组实验：

Clean:   只给 T 之前证据（随机顺序）
Leaky:   给 T 之前证据 + T+1 泄漏证据（随机顺序）
Audited: 给 Clean+Leaky 全部证据 → 先让模型做 Leaky 预测 
         → FinLeakAudit 审计 rationale，识别被泄漏证据支持的 claims
         → 删除污染证据 → 重新生成预测（leakage-driven revision）
```

> ⚠️ Audited 不是 "预测前先过滤未来证据"，而是 **"先 Leaky 预测 → 审计 rationale → ablate → revise"**。否则会退化成简单时间过滤，失去 novelty。

### 1.3 样本量

- **Pilot**: 10 个 case（验证 pipeline、prompt、数据格式）
- **Full**: 扩容到 50 个 case（达到统计显著所需样本量）
- **Calibration check**: 额外 10 个 case，证据全部 irrelevant

## 5. FinLeakAudit v0.1 实现

### 5.1 Operator 1: Temporal Availability Checker

```python
def temporal_availability_check(evidence_list, prediction_date):
    """
    Check each evidence item's temporal validity.
    prediction_date is "Day T" — any evidence with time "T+*" is future.
    """
    results = []
    for ev in evidence_list:
        time_str = ev["time"]
        if time_str.startswith("T+"):
            status = "future_leakage"
            severity = "high" if time_str in ["T+1", "T+2"] else "medium"
        else:
            status = "valid"
            severity = "none"
        results.append({
            "evidence_id": ev["id"],
            "time": time_str,
            "temporal_status": status,
            "severity": severity,
        })
    return results
```

### 5.2 Operator 2: Rationale Leakage Detector

```python
def detect_rationale_leakage(rationale, temporal_results):
    """
    Check if any claims in rationale cite future evidence.
    temporal_results: output of temporal_availability_check()
    """
    future_ids = {r["evidence_id"] for r in temporal_results 
                  if r["temporal_status"] == "future_leakage"}
    
    leaked_claims = []
    for claim in rationale:
        cited_ids = set(claim.get("evidence_ids", []))
        leaked = cited_ids & future_ids
        if leaked:
            leaked_claims.append({
                "claim": claim["claim"],
                "leaked_evidence_ids": list(leaked),
                "all_cited_ids": list(cited_ids),
            })
    
    return {
        "has_leakage": len(leaked_claims) > 0,
        "leaked_claims": leaked_claims,
        "leakage_count": len(leaked_claims),
        "total_claims": len(rationale),
    }
```

### 5.3 Semantic Leakage Detector

```python
def detect_semantic_leakage(rationale, leaked_evidence_texts, model="deepseek"):
    """
    Detect if rationale semantically mirrors leaked evidence
    without explicitly citing its evidence_id.
    
    Two strategies:
    1. embedding similarity: cosine similarity between claim and leaked evidence
    2. LLM judge: ask model whether claim is "supported by" leaked evidence
    """
    leaked_claims = []
    for claim in rationale:
        cited_ids = set(claim.get("evidence_ids", []))
        for lev in leaked_evidence_texts:
            # Skip if already caught by citation detection
            if lev["id"] in cited_ids:
                continue
            # Strategy 1: embedding similarity
            sim = cosine_similarity(embed(claim["claim"]), embed(lev["text"]))
            if sim > 0.75:
                leaked_claims.append({
                    "claim": claim["claim"],
                    "matched_evidence_id": lev["id"],
                    "match_type": "semantic_overlap",
                    "similarity": sim,
                })
    return {
        "has_semantic_leakage": len(leaked_claims) > 0,
        "semantic_leaked_claims": leaked_claims,
        "semantic_leakage_count": len(leaked_claims),
    }
```

### 5.4 Audit Pipeline (updated)

```python
def finleakaudit_audit(case, prediction_output):
    """
    Full audit pipeline for v0.1.
    """
    # Step 1: Check temporal availability
    temp_results = temporal_availability_check(
        case["clean_evidence"] + case["leaked_evidence"],
        case["prediction_date"],
    )
    
    # Step 2: Detect rationale leakage (citation)
    leakage_report = detect_rationale_leakage(
        prediction_output["rationale"],
        temp_results,
    )
    
    # Step 3: Detect semantic leakage
    leaked_texts = [
        {"id": e["id"], "text": e["text"]}
        for e in case.get("leaked_evidence", [])
    ]
    semantic_report = detect_semantic_leakage(
        prediction_output["rationale"],
        leaked_texts,
    )
    
    # Step 4: Identify all leaked evidence (citation + semantic)
    removed_ids = set()
    for lc in leakage_report["leaked_claims"]:
        removed_ids.update(lc["leaked_evidence_ids"])
    for sc in semantic_report["semantic_leaked_claims"]:
        removed_ids.add(sc["matched_evidence_id"])
    
    # Step 5: Filter evidence
    valid_evidence = [
        ev for ev in (case["clean_evidence"] + case["leaked_evidence"])
        if ev["id"] not in removed_ids
    ]
    
    return {
        "leakage_detected": leakage_report["has_leakage"],
        "leakage_report": leakage_report,
        "temporal_check": temp_results,
        "removed_evidence_ids": list(removed_ids),
        "valid_evidence": valid_evidence,
    }
```

## 8. 风险与预案

| 风险 | 概率 | 影响 | 预案 |
|---|---|---|---|---|
| 模型不引用 evidence_id | 中 | 高 | 1. 强化 prompt 约束 2. 换 DeepSeek / GPT-4o 3. 依赖 semantic leakage 检测 |
| 模型用 internal knowledge | 高 | 中 | 报告 internal knowledge usage rate，作为 limitation |
| JSON 格式解析失败 | 中 | 低 | retry + regex fallback |
| Calibration check 失败 (假归因 > 15%) | 中 | 高 | 换 prompt / 换模型 / 放弃 attribution，改用 post-hoc 语义匹配 |
| Recency bias（T+1 总在最后） | 高 | 中 | **已解决**：evidence 顺序随机化 + seed 记录 |
| 缺乏真实 label 导致指标空洞 | 中 | 中 | Phase 1 不报 Accuracy，Phase 2 转为真实 events |
| Qwen 本地太慢 | 低 | 低 | 先跑 5–10 测速，overnight 跑完 |
| 泄漏案例不够多 | 低 | 中 | 增强 leaked evidence 的信号强度 |
| API 费用超预期 | 低 | 低 | 先从 20 case pilot 开始 |
| Semantic leakage 标注不可靠 | 中 | 中 | 双标注 + Cohen's κ；低 κ 则仅报告 citation leakage |
